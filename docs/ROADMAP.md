# Matharium — خطة الميزات

خمس جلسات عمل، كل جلسة تُنفَّذ في **جلسة Claude Code مستقلة**، على **فرع مستقل**، وتنتهي بـ **Pull Request** يمر على GitHub Actions.
المرحلة أ كبيرة فقُسمت إلى جلستين (أ1 ثم أ2).

| الجلسة | المحتوى | يعتمد على | الفرع |
| :--- | :--- | :--- | :--- |
| **أ1** | الكسور والقيم الدقيقة + التحليل إلى عوامل | — | `feature/a1-exact-factor` |
| **أ2** | خطوات الحل | أ1 | `feature/a2-steps` |
| **ب** | الإحداثيات القطبية + الانحدار غير الخطي + التحريك والتسجيل | — | `feature/b-polar-fit-animate` |
| **ج** | النصوص والتعليقات + ورقة عمل PDF + قوالب الدروس | — | `feature/c-teacher` |
| **د** | الإكمال التلقائي + أدوات التفاضل والتكامل + الإحصاء + النقطة المقيّدة | — | `feature/d-pro` |

**الترتيب المقترح:** أ1 ← أ2 ← ب ← ج ← د، جلسة بعد دمج التي قبلها.
الجلسات ب وج ود لا تعتمد على أ منطقياً، لكنها كلها تعدّل ملفات مشتركة (`engine.ts`، `parser.ts`، `i18n.ts`، `store/project.ts`). تشغيلها في وقت واحد ممكن (كلٌّ في worktree مستقل)، لكن توقّع حل تعارضات عند الدمج.

## طريقة تشغيل جلسة

**من تطبيق Claude (Code):** افتح جلسة جديدة على المجلد `D:\math`، والصق أمر الجلسة الموجود تحت كل مرحلة.

**من الطرفية:**
```bash
cd /d/math && git checkout main && git pull
```
ثم الأمر الخاص بالجلسة، مثلاً:
```bash

```

بعد انتهاء الجلسة: راجع الـ PR، تأكد أن CI أخضر، ادمجه، ثم ابدأ الجلسة التالية من `main` المحدَّث.

## قواعد مشتركة لكل جلسة

اقرأ هذا القسم قبل البدء في أي جلسة.

1. **ابدأ من `main` محدَّث** وأنشئ فرع الجلسة. اقرأ `README.md` وافهم البنية الحالية قبل التعديل:
   - `src/math/parser.ts`: `splitDefinition`، `asCommand`، `COMMAND_CAT`، `categorize`.
   - `src/math/engine.ts`: الصنف `Engine` (الدالة `command()` بها كل الأوامر في `switch`)، و`evaluateAll`، و`tryTex`.
   - `src/math/compile.ts`: `parseExpr`، `compileFn` (يحوّل mathjs إلى JS سريع)، `toTex`، `texName`.
   - `src/math/types.ts`: نوع `Value` (أضف أنواعاً جديدة هنا).
   - `src/graph2d/renderer.ts`: `drawValue()` يرسم كل نوع، ويعمل مع `SvgCtx` أيضاً (للتصدير).
   - `src/graph3d/meshes.ts`: `build()` لكل نوع في العرض ثلاثي الأبعاد.
   - `src/store/project.ts`: الحالة. **كل وضع (graphing/geometry/3d) له مساحة عمل مستقلة** (`workspaces`).
   - `src/i18n/i18n.ts`: كل نص جديد يُضاف **بالإنجليزية والعربية** معاً.
   - `src/components/Dialogs.tsx`: قائمة المساعدة `HELP`. أضف أمثلة لكل أمر جديد.
2. **الأسلوب:** طابِق نمط الكود الموجود. لا مكتبات من CDN ولا طلبات شبكة خارجية، فالتطبيق يجب أن يعمل **دون إنترنت** (PWA). أي مكتبة جديدة تُثبَّت من npm بإصدار مثبّت.
3. **الاختبارات إلزامية:**
   - اختبارات وحدة (vitest) لكل منطق رياضي جديد، بجانب الملف (`*.test.ts`).
   - اختبار متصفح (Playwright) لكل ميزة واجهة في `e2e/`، باستخدام المساعدات في `e2e/helpers.ts`.
   - قبل الـ PR يجب أن تنجح كلها:
     ```bash
     npm run build && npm test && npm run e2e
     ```
   - لا تُضعف الاختبارات الموجودة. ميزانية الأداء في `src/math/edge.test.ts` يجب أن تبقى ناجحة.
4. **التحقق اليدوي:** شغّل التطبيق (`npm run dev`) وجرّب الميزة فعلياً بالإنجليزية والعربية، على سطح المكتب وبعرض جوال.
5. **الإنهاء:**
   - commit واضح، ثم push للفرع، ثم PR إلى `main` يشرح ما أُضيف وكيف اختُبر.
   - انتظر نتيجة CI وأصلح أي فشل.
   - **لا تدمج الـ PR**: الدمج قرار صاحب المشروع.
   - حدّث هذا الملف: علّم بنود الجلسة كمنجزة ✅.

## الجلسة أ1: القيم الدقيقة والتحليل إلى عوامل

**أمر التشغيل:**
```bash
claude "Implement session A1 from docs/ROADMAP.md"
```

**الهدف:** أن يرى الطالب النتائج بصيغتها الرياضية الدقيقة، لا عشرية فقط.

**المطلوب:**
- [ ] **وحدة رموز دقيقة** جديدة `src/math/exact.ts`:
  - `toExact(v: number)` تتعرف على: الكسور `p/q` (مقام ≤ 1000)، ومضاعفات `π` النسبية، والجذور `p/q·√n`، والصيغة `(a ± b√n)/c`. تُرجع LaTeX ونصاً، أو `null` إن لم تجد صيغة موثوقة (تسامح ~1e-10).
  - كثيرات الحدود: استخراج المعاملات من التعبير (`math.rationalize(..., true)` يعطي `coefficients`) مع حساب بالكسور الدقيقة (`math.fraction`).
- [ ] **زر ≈ لكل سطر** في `AlgebraPanel`: يبدّل بين الدقيق والعشري. الإعداد الافتراضي «دقيق» يُضاف في `Settings`.
  - يطبَّق على: الأعداد، وإحداثيات النقاط، ونتائج `Solve` و`Roots` و`Intersect` و`Extremum` و`Integral`.
- [ ] **حلول دقيقة للمعادلات:** `Solve` لكثيرات حدود من الدرجة ≤ 2، وأي كثيرة حدود جذورها نسبية، تعرض الجذور الدقيقة مثل `x = (3 ± √17)/4`. الحل العددي الحالي يبقى للباقي.
- [ ] **أمر `Factor(expr)`**: العامل المشترك، ثم الفرق بين مربعين، ثم مبرهنة الجذور النسبية مع القسمة التركيبية، ثم تحليل التربيعي المتبقي إن أمكن فوق الأعداد النسبية. يرجع دالة (تُرسم) ويُعرض بصيغته المحللة.
  - أمثلة: `Factor(x^3 - 6x^2 + 11x - 6)` يعطي `(x−1)(x−2)(x−3)`، و`Factor(2x^2 - 8)` يعطي `2(x−2)(x+2)`، و`Factor(x^2 + 1)` يبقى كما هو.
- [ ] أضف `Factor` إلى `COMMAND_CAT` وإلى أزرار f(x) في لوحة المفاتيح (`MathKeyboard.tsx`) وإلى قائمة المساعدة.

**معايير القبول:**
- `Solve(2x^2 - 3x - 1 = 0)` يعرض `x = (3 − √17)/4, x = (3 + √17)/4`، وبزر ≈ يعرض القيم العشرية.
- `Integral(x^2, 0, 1)` يعرض `1/3`، و`sin(pi/4)` يعرض `√2/2`، و`Angle` القائمة تعرض `90°` و`π/2`.
- اختبارات وحدة لـ `toExact` (≥ 30 حالة، منها حالات يجب أن ترجع `null` مثل `0.123456789`) ولـ `Factor` (≥ 15 حالة). اختبار متصفح لزر ≈.
